
| Assumption Challenged | Test input/environment | Failure and how it's detected| 
| --- | --- | ---|
| Every download is small, quick and arrives with a known size. |A very large file, a response that never ends, a server that sends one byte per second, and a chunked response with no Content-Length header | The scraper runs out of memory, hangs forever because it has no timeout, or prints a size that does not match what actually arrived. Watch memory use, put a time limit on the whole run, and compare the reported size with the number of bytes the server really sent. |
Any link ending in .pdf, .docx etc. is a real documents | links like policy.PDF (uppercase), policy.pdf?v=2 (query string), policy.pdf.html (decoy), /download?id=12 (no extension) | False positives occur when fake documents are counted as downloaded policies, and false negatives occur when extensionless documents are silently missed. Check which links are real documents, compare scraper's list with own list |
Links are simple, absolute-resolvable and unique | Index page containing href="",javascript:void(0), ../../x.pdf, the same PDF twice with different #fragments, URL-encoded or unicode filenames | duplicate files get downloaded twice, non-HTTP schemes are requested and crash, or relative links resolve incorrectly. Can detect by counting the distinct URLS requested in the server's access log |
Text is UTF-8 and the HTML is well-formatted | index page given as a mismatched charset declaration, links only inside onclick or inline JS | Results in garbled URLs, links are silently missed or a UnicodeEncodeError when printing. Compare these results to the requested URLs in the server log and check them against the expected one. |
The network path is clean (TLS is valid, open, same-origin etc.) | Use a local HTTPS server with self-signed or expired certificate, a host that resolves to several IPs where one is dead, one is a proxy-only network and a server that sends bad content-encoding | Scraper crashes on the SSL or decompression error, or silently turns off certificate checking to get past the problem, causing security issues. Detect this by the exit code and error text and confirm that each failing URL receives its own clear error |
Links stay on the same site, and the site isn't hostile | Site links to another host, a redirect chain and file:// or localhost link | Fails if the scraper follows off-site or internal redirects, or loops until the requests cap. Detect this from the server logs and count how many requests have been made. |
